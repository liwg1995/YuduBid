# 导出反馈与请求隔离验收

2026-10-29，design分支。

## 修改范围

论文、项目协作、公文、课题共7类导出入口：论文Word、项目协作共用阶段/全套Word、公文Word、课题当前/全套阶段Word及定稿包/填报包/模板栏目稿三类Word包。

- 共用wordExportFeedback只判断服务返回、匹配requestId并规范最后进度，不接管Main任务或文件写入。
- 非取消结果必须明确success=true，否则按失败展示。此前课题/公文会把success=false当成功，项目协作/论文部分路径不结束running；现均落到错误状态并允许重试。
- 方法级Ref锁阻止连续调用；项目协作另有响应式pending，进度事件先结束时仍等待本次Promise完成。finally释放，取消不作失败处理。
- 错误沿用本轮最后进度，不再在Renderer人为设置100%。成功返回补齐success/100%，即便没有最后一条IPC事件也能正确结束。
- 进度只接受对应请求编号；Main exportIpc.cjs已将本次requestId附在export:word-progress上，未改bridge契约。无编号或其他请求事件不进入当前进度。请求ID增加随机后缀，避免同毫秒重试碰撞。
- 论文生命周期监听不再无差别接收全局导出事件，也不与操作Hook重复弹出完成/错误Toast；仅更新本轮对应进度，终态提示由操作结果发出。
- 课题四类Word导出在等待第一次进度前即显示准备状态；原有内容、配置、取消和文件选择逻辑保留。

## 实际验证

真实useProjectManagementExport、useThesisTutorOperations及useThesisTutorLifecycle，配置/业务/导出桥接均为隔离模拟，无真实文件输出。

两类Hook各覆盖失败返回、抛出异常、取消、成功4种情况，共8条路径：每次同一事件连续调用方法两次，只有一次导出请求；请求总数从1递增至8。模拟本轮37%后广播other-module的99%成功事件，两个工作区仍保持本轮37%，没有误报完成。

失败返回及异常均为error/37%，成功为success/100%，取消为canceled/0；项目操作锁最终false，后续模式可以再次导出。论文成功在无最终成功进度事件时也正确结束，完成Toast单次发出。最终随机ID版本另复测项目失败路径，仍为单请求/error37%。

公文和课题页面中的5类接入由TypeScript构建验证及源调用审查，未运行完整页面导出。UI复制/导出当前稿件权威关系沿用原页面，未重新定义保存与正文来源。本轮不代表真实Word版式、文件选择、生成或原生窗口回归完成。

npm run build、git diff --check通过，仅既有chunk体积提示。无依赖、Main、IPC修改；无用户资料读写。
