# 双平台未签名发布验收指南

## 当前发布边界

当前 macOS 和 Windows 版本均按未签名模式构建：

- macOS 使用 `identity: null`，不使用 Developer ID，不执行公证。
- Windows 使用 `signExecutable: false`，保留应用图标和版本信息，但不执行 Authenticode 签名。
- 根配置使用 `forceCodeSigning: false`，构建不会因缺少证书失败。
- 不配置 `CSC_LINK`、`CSC_NAME`、`WIN_CSC_LINK`、Azure Trusted Signing 或时间戳服务。

未签名产物出现 macOS Gatekeeper 或 Windows SmartScreen 提示属于当前版本的已知行为，不作为功能缺陷。

## 自动检查

在 `client/` 目录执行：

```powershell
npm run verify:software-copyright:release
npm run verify:software-copyright:artifact -- "release/mac-arm64/禹都AI解决方案助手.app"
npm run verify:software-copyright:artifact -- release/win-unpacked
npm run verify:unsigned-artifacts
```

`verify:unsigned-artifacts` 会检查：

- 配置没有启用证书签名。
- Windows 主程序和 NSIS 安装包的 PE 证书目录为空。
- macOS 应用没有有效的完整证书签名、Authority 或 TeamIdentifier。

macOS Mach-O 可能保留编译器生成的 linker ad-hoc 标记，这不代表应用完成了 Developer ID 签名；验收以不存在证书 Authority、团队标识且严格签名校验不通过为准。

## Windows 现场启动检查

把完整仓库或 `release/` 产物复制到真实 Windows x64 机器后，在项目 `client/` 目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-windows-release.ps1
```

脚本会：

1. 检查主程序和安装包均为 `NotSigned`。
2. 创建带中文名称的临时项目和隔离用户数据目录。
3. 启动 `win-unpacked` 应用两次。
4. 验证第二次启动不会清空工作区保留标记。
5. 输出 JSON 验收结果并清理临时数据。

需要保留现场目录排查时增加 `-KeepData`。

## Windows 人工业务验收

自动脚本通过后，仍需在界面中完成：

1. 使用中文 Windows 用户名登录，选择包含中文和空格的项目路径。
2. 新建软著项目，扫描源码并检查包含、排除和手工补充规则。
3. 导入 PNG/JPEG 截图，生成草稿并完成确认快照。
4. 导出 DOCX、TXT、ZIP、交付清单和申报提交说明。
5. 关闭客户端后重新启动，确认项目、草稿、图片和交付批次仍在。
6. 检查导出文件能由 Microsoft Word 和系统压缩工具正常打开。

## 安装、覆盖升级和卸载验收

1. 备份 `%APPDATA%` 下本应用的用户数据目录。
2. 运行 NSIS 安装包，记录 SmartScreen 提示和安装目录。
3. 启动应用并创建一份带明显标记的软著项目。
4. 关闭应用，使用同版本或后续候选版本覆盖安装。
5. 再次启动，确认用户配置、工作区和软著项目未丢失。
6. 卸载应用，确认程序目录被移除。
7. 检查用户数据是否按照发布策略保留；当前阶段不得在未确认备份的情况下手工删除用户数据。
8. 重新安装并确认保留的工作区能够再次读取。

## macOS 人工验收

1. 在 Finder 中打开 `.app`；首次启动如被系统拦截，使用系统提供的“仍要打开”流程。
2. 使用中文和空格路径完成软著源码扫描、截图导入与正式导出。
3. 关闭并重新启动应用，检查工作区恢复。
4. 检查 DOCX 和 ZIP 产物能够正常打开。
5. 不执行 `codesign`、`xcrun notarytool` 或临时 ad-hoc 重签名来掩盖未签名状态。

## 验收记录

完成现场验证后，将机器版本、Windows/macOS 版本、架构、产物 SHA-256、验收日期和遗留问题填写到《软著模块发布候选版验收清单》。
