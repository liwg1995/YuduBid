## 自动验收

- [ ] 在 `client/` 执行 `npm ci`，依赖安装完成。
- [ ] 执行 `npm run verify:software-copyright:release`，全部检查通过。
- [ ] 完成目录打包后执行 `npm run verify:software-copyright:artifact -- <产物路径>`，产物检查通过。
- [ ] 启动打包后的客户端，主进程和 Renderer 无启动错误。
- [ ] 确认产物版本、平台和架构与发布计划一致。
- [ ] 执行 `npm run verify:unsigned-artifacts`，确认 macOS 和 Windows 产物均未使用证书签名。

## 项目与数据验收

- [ ] 新建软著项目，项目名称、软件名称和版本号保存正常。
- [ ] 复制项目后，原项目和副本可以独立编辑。
- [ ] 归档项目后默认列表隐藏，切换筛选后可以重新查看。
- [ ] 使用包含中文名称和中文路径的项目目录完成扫描。
- [ ] 客户端任务中途退出后重新打开，显示可理解的中断恢复提示。
- [ ] 关闭客户端并备份软著工作区，恢复后项目、草稿和历史批次完整。
- [ ] Windows 现场执行 `scripts/verify-windows-release.ps1`，两次启动和工作区保留检查通过。

## 代码材料验收

- [ ] 扫描结果包含预期源码，不包含构建目录、依赖目录和排除文件。
- [ ] 手动补充与排除源码文件后，代码材料按新规则重新生成。
- [ ] 前30页、后30页和不足60页三种规则符合实际代码行数。
- [ ] 代码审查未发现密钥、令牌、身份证号或其他不应提交的信息。
- [ ] TXT 与 DOCX 中的代码顺序、页码和内容一致。

## 草稿与图片验收

- [ ] 生成申请表、操作手册、代码材料和生成报告草稿。
- [ ] 修改草稿后形成历史版本，并能恢复指定版本。
- [ ] 手工截图可以导入、排序、填写说明和删除。
- [ ] AI 配图生成失败时有明确提示，已有草稿不会丢失。
- [ ] 图片在操作手册中的位置、清晰度和说明符合提交要求。

## 检查、确认与导出验收

- [ ] 完整检查覆盖必填字段、跨材料一致性、代码和图片风险。
- [ ] 存在阻断问题时不能误认为材料已可提交。
- [ ] 确认草稿后生成不可变快照和摘要清单。
- [ ] 修改字段、草稿、图片或代码规则后，旧确认状态自动失效。
- [ ] 正式导出只使用当前确认快照，不受确认后的临时编辑影响。
- [ ] 连续导出形成独立批次，历史批次仍可打开和核验。
- [ ] ZIP、交付清单和各文件摘要一致。

## 申报辅助验收

- [ ] 24个申报字段均能展示并复制。
- [ ] 字段缺失、长度异常、文件命名和权属材料风险提示准确。
- [ ] 《申报提交说明》可以重新生成，并进入正式批次和 ZIP。
- [ ] 官网填报值与申请表、操作手册及确认快照一致。

## 已知发布约束

- 当前 Windows 和 macOS 产物未接入代码签名，系统可能显示安全提示。
- 本阶段不执行 macOS 公证、Developer ID 签名、Windows Authenticode 或 Azure Trusted Signing。
- 自动验收不能代替登记机构口径、权属证明和最终提交材料的人工审核。
- Windows 产物应在真实 Windows x64 环境再次启动，并验证中文路径、文件选择和 Word/ZIP 导出。
