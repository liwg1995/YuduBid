## 2026-10-27：复杂文档样本与表格预览

### 定位及修复

1. 真实 Electron 导入合成 DOCX 后，日志显示 `globalExists=false / scopedExists=true`：图片实际在可研项目独立工作区，URL 沿用 imported-images，而原生协议与导出只查全局图片目录。原始回归明确失败并产生“未找到可用图片数据”警告。
2. 在 `electron/utils/importedImages.cjs` 增加共用的可研图片查找，由原生资源协议和 Word 图片加载共同调用；全局路径不存在时，仅在有效可研项目的 imported-images 内查找本功能生成的批次。保留原 URL、文件与存储契约；不把项目目录设为通用资源根。路径穿越和其他功能批次拒绝查找。
3. DOCX 横向合并表格中的 `<p>` 原被当作内联未知 HTML，既出现降级提示，也把多段文字粘连。导出现在保留单元格的独立段落和原横向合并。
4. Renderer 原先将 HTML 表格压平为 GFM 文本，丢失合并属性和段落边界。改为安全的 Markdown AST 表格转换：仅输出文本、换行及受限 colSpan/rowSpan，不复制原始事件/样式，不启用 rehypeRaw；代码块中的 HTML 不被误转换。
5. 资料阅读器表格补齐主题边框、8×12px 单元格内边距、14/22 字阶、左对齐与顶部对齐；导入失败分段展示原因及“本批次未导入，原有资料和成果保留”。无文字层 PDF 提供替换带文字层 PDF 或选择 OCR 解析方式的建议。
