# 可研报告功能设计

## 1. 文档状态

- 当前阶段：阶段四已完成，准备进入资料分析、报告目录和关键参数实现。
- 当前结论：菜单、页面骨架、多项目工作区、SQLite v16、基础信息表单、批量资料解析、Markdown 预览、资料移除和下游失效已落地；AI 任务和导出尚未接入。
- 来源参考：`FB208/OpenBidKit_Yibiao` 的 `feasibility-report` 功能。
- 本项目适配原则：参考业务流程和 Prompt 设计，不覆盖本项目现有公共文件，不引入来源项目的埋点、插件或 Agent 工作区依赖。

## 2. 产品目标

在“招投标”一级模块下新增“可研报告”二级菜单，为不同项目建立互相隔离的可行性研究报告工作区，完成以下闭环：

1. 创建并管理可研项目。
2. 填写项目基础信息。
3. 导入项目资料并解析为 Markdown。
4. 使用用户已配置的文本模型完成资料分析。
5. 选择可研大纲模板并生成、编辑报告目录。
6. 生成关键参数和全文统一口径。
7. 按目录叶子小节生成、编辑和审校正文。
8. 导出带封面、编制说明、目录、附表和 Mermaid 图片的 Word 文档。

菜单展示名称统一使用“可研报告”，内部导航 ID 使用 `feasibility-report`，代码目录使用 `features/feasibility-report/`。

## 3. 本期范围

### 3.1 纳入范围

- 多项目创建、切换、重命名和删除。
- 六步工作流：项目资料、资料文件、资料分析、报告目录、关键参数、正文生成。
- 政府投资、企业投资以及行业型目录模板。
- 本地文件导入、Markdown 解析和图片资产管理。
- 知识库文档选择和轻量知识条目引用。
- 资料分析、目录生成、目录 AI 调整、关键参数、正文生成和自然化审校后台任务。
- 正文暂停、继续、缺失章节补写和任务异常恢复。
- Markdown 编辑、预览和 Mermaid 本地渲染。
- Word 导出及导出进度反馈。

### 3.2 不纳入范围

- 来源项目中的远程埋点、访问统计和公告服务。
- 来源项目中的插件宠物、插件安装提示和插件事件通知。
- 来源项目中的持久化 Agent 会话和 Agent 工作区管理。
- 独立的“导出模板中心”；第一版使用本项目现有 Word 导出能力和可研专用选项。
- 自动联网搜索政策、价格、市场数据或行业资料。
- 替代注册咨询工程师、造价、财务、法律或行业专家的最终审核。
- 将原始 Word、PDF 等文件长期复制进工作区；只保存解析后的 Markdown、元数据和导入图片。

## 4. 页面与流程

### 4.1 项目入口

首次进入“可研报告”时展示项目管理页：

- 项目名称为必填项。
- 支持创建、搜索、切换、重命名和删除项目。
- 项目列表展示当前步骤、更新时间和正文完成进度。
- 创建项目后进入该项目独立的六步工作区。
- 删除项目必须使用项目内 Dialog 二次确认；存在运行任务时先停止任务，成功停止后再删除。

### 4.2 六步工作流

| 步骤 | 页面职责 | 主要产物 |
| --- | --- | --- |
| 项目资料 | 填写项目名称、类型、行业、建设单位、地点、建设内容、周期、投资额和资金来源 | `projectInfo` |
| 资料文件 | 批量导入、解析、预览和移除项目资料 | `sourceFiles`、Markdown 文件 |
| 资料分析 | 基于项目参数和全部资料提取事实、缺口、风险、编制依据和待确认事项 | `analysis.md` |
| 报告目录 | 选择模板、目标字数和知识库引用，生成或编辑最多三级目录 | `outlineData` |
| 关键参数 | 统一投资、建设内容、周期、指标和测算口径 | `key-parameters.md` |
| 正文生成 | 按叶子小节生成、补写、编辑、审校、预览和导出 | `outline[*].content` |

步骤导航允许回看已完成步骤。进入后续步骤前校验必要前置条件，不依赖 Renderer 临时状态判断数据是否存在。

## 5. 多项目工作区设计

### 5.1 总体方式

沿用技术方案现有的项目隔离方式：项目注册表保存在主工作区，每个项目使用独立的 scoped `userData` 和 SQLite 数据库。

```text
userData/
  workspace/
    feasibility-report/
      projects.json
  feasibility-report-projects/
    <projectId>/
      workspace/
        yibiao.sqlite
        feasibility-report/
          analysis.md
          key-parameters.md
          sources/
            <sourceId>.md
        imported-images/
          feasibility-report-*/
```

说明：

- `projects.json` 只保存项目注册信息和活动项目 ID，不保存业务正文。
- 每个项目的数据库和文件互相隔离，避免新项目覆盖旧项目。
- scoped app 继续通过 `app.getPath('userData')` 派生路径，不在业务代码中拼接用户主目录。
- 项目 ID 使用 `fr-<timestamp>-<random>`，只允许小写字母、数字、下划线和短横线。
- 第一版不存在来源项目旧单例数据，因此不设计旧可研数据迁移。

### 5.2 项目注册表

```ts
interface FeasibilityProjectRecord {
  id: string;
  name: string;
  created_at: string;
  updated_at: string;
}

interface FeasibilityProjectRegistry {
  activeProjectId?: string;
  projects: FeasibilityProjectRecord[];
}
```

注册表写入必须显式使用 UTF-8。删除项目时关闭缓存数据库连接，并只删除已解析、已校验的具体项目目录。

## 6. Renderer 状态模型

```ts
type FeasibilityReportStep =
  | 'materials'
  | 'sources'
  | 'analysis'
  | 'outline'
  | 'parameters'
  | 'content';

type FeasibilityTaskType =
  | 'feasibility-analysis'
  | 'feasibility-outline'
  | 'feasibility-outline-adjustment'
  | 'feasibility-parameters'
  | 'feasibility-content'
  | 'feasibility-human-writing';

interface FeasibilityReportState {
  projectId: string;
  projectName: string;
  step: FeasibilityReportStep;
  projectInfo: FeasibilityProjectInfo;
  sourceFiles: FeasibilitySourceFile[];
  analysisMarkdown: string;
  outlineTemplate: FeasibilityOutlineTemplate;
  targetWords: number;
  referenceDocumentIds: string[];
  keyParametersMarkdown: string;
  outlineData: OutlineData | null;
  contentSections: Record<string, FeasibilityContentSectionState>;
  analysisTask?: FeasibilityBackgroundTaskState;
  outlineTask?: FeasibilityBackgroundTaskState;
  outlineAdjustmentTask?: FeasibilityBackgroundTaskState;
  parametersTask?: FeasibilityBackgroundTaskState;
  contentTask?: FeasibilityBackgroundTaskState;
  humanWritingTask?: FeasibilityBackgroundTaskState;
}
```

Renderer 只持有当前项目快照，不把业务状态写入 `localStorage`。任务事件必须携带 `projectId`；页面忽略其他项目的事件补丁。

## 7. SQLite 设计

### 7.1 版本策略

- 当前 runtime `schemaVersion` 为 15。
- 实现时计划使用下一版本 16；若实施前仓库版本已变化，则使用当时的 `schemaVersion + 1`，不得复用已有版本号。
- 不复制来源项目 v16-v23 的整段 migration，只新增本项目需要的可研表结构。
- runtime migration 和根目录 `sql/workspace_schema.sql` 必须同步更新。

### 7.2 feasibility_report_meta

每个 scoped 数据库只保留一行 `id = 1`：

- `step`
- `project_info_json`
- `analysis_markdown_path`、`analysis_markdown_hash`、`analysis_markdown_chars`
- `outline_template`
- `target_words`
- `key_parameters_markdown_path`、`key_parameters_markdown_hash`、`key_parameters_markdown_chars`
- `outline_project_name`、`outline_project_overview`
- `created_at`、`updated_at`

项目名称以注册表为权威来源；`project_info_json.projectName` 是报告内容字段，两者允许不同，但创建项目时默认保持一致。

### 7.3 feasibility_report_sources

每份解析资料一行：

- `source_id TEXT PRIMARY KEY`
- `file_name TEXT NOT NULL`
- `markdown_path TEXT NOT NULL`
- `markdown_chars INTEGER NOT NULL DEFAULT 0`
- `content_hash TEXT NOT NULL`
- `parser_label TEXT`
- `sort_order INTEGER NOT NULL DEFAULT 0`
- `imported_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

Markdown 正文保存到 `feasibility-report/sources/<sourceId>.md`，SQLite 不保存原始大文本。

### 7.4 feasibility_report_reference_docs

保存选中的知识库文档：

- `document_id TEXT PRIMARY KEY`
- `sort_order INTEGER NOT NULL DEFAULT 0`

只保存引用 ID；读取时跳过不存在、未完成或无有效知识条目的文档。

### 7.5 feasibility_report_tasks

保存六类后台任务状态：

- `type TEXT PRIMARY KEY`
- `task_id TEXT NOT NULL`
- `status TEXT NOT NULL`
- `progress INTEGER NOT NULL DEFAULT 0`
- `logs_json TEXT`
- `stats_json TEXT`
- `error TEXT`
- `pause_requested INTEGER NOT NULL DEFAULT 0`
- `started_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

任务日志按关键阶段更新，不按 token 或流式 chunk 落盘。

### 7.6 feasibility_report_outline_nodes

保存目录树和正文，是正文展示与导出的权威来源：

- `node_id TEXT PRIMARY KEY`
- `parent_node_id TEXT`
- `sort_order INTEGER NOT NULL`
- `level INTEGER NOT NULL`
- `title TEXT NOT NULL`
- `description TEXT NOT NULL DEFAULT ''`
- `knowledge_item_ids_json TEXT`
- `content TEXT NOT NULL DEFAULT ''`
- `content_source TEXT NOT NULL DEFAULT 'none'`：`none` / `ai` / `manual`
- `created_at TEXT NOT NULL`
- `updated_at TEXT NOT NULL`

目录最多三级。目录重新生成、排序、编辑、添加或删除后，清空全部旧正文和正文生成缓存。

### 7.7 feasibility_report_content_sections

保存叶子小节生成状态，不重复保存正文：

- `node_id TEXT PRIMARY KEY`
- `status TEXT NOT NULL DEFAULT 'idle'`
- `error TEXT`
- `updated_at TEXT NOT NULL`
- 外键关联 `feasibility_report_outline_nodes(node_id)` 并级联删除。

## 8. Store 与 IPC 边界

### 8.1 Electron Main 服务

- `feasibilityReportStore.cjs`：单项目 SQLite 和文件读写。
- `feasibilityReportStoreRouter.cjs`：项目注册表、项目切换和 scoped Store 缓存。
- `feasibilityReportTasks.cjs`：资料分析、关键参数、正文和自然化任务。
- `feasibilityOutlineTask.cjs`：目录生成和目录结构校验。
- `feasibilityOutlineAdjustmentTask.cjs`：基于当前完整目录进行无会话 AI 调整。
- `feasibilityReportPrompts.cjs`：全部可研 Prompt 和输出 Schema。
- `feasibilityReportIpc.cjs`：只注册和转发 IPC。

### 8.2 feasibilityReport bridge

计划提供以下接口：

- `listProjects()`
- `createProject(payload)`
- `renameProject(payload)`
- `deleteProject(payload)`
- `switchProject(payload)`
- `loadState(payload)`
- `updateStep(payload)`
- `saveProjectInfo(payload)`
- `importSourceDocuments(payload)`
- `removeSourceDocument(payload)`
- `readSourceMarkdown(payload)`
- `readCombinedSourceMarkdown(payload)`
- `saveAnalysis(payload)`
- `saveOutlineConfig(payload)`
- `saveOutline(payload)`
- `saveKeyParameters(payload)`
- `saveChapterContent(payload)`
- `clearProject(payload)`

除创建项目外，所有接口都显式携带 `projectId`。Renderer 不向任务接口传递整份资料或正文大文本。

### 8.3 tasks bridge

计划新增：

- `startFeasibilityAnalysis(payload)`
- `startFeasibilityOutline(payload)`
- `startFeasibilityOutlineAdjustment(payload)`
- `startFeasibilityParameters(payload)`
- `startFeasibilityContent(payload)`
- `pauseFeasibilityContent(payload)`
- `stopFeasibilityContent(payload)`
- `startFeasibilityHumanWriting(payload)`

所有任务载荷包含 `projectId`。任务从 Store 读取项目资料、分析、目录和正文，不信任 Renderer 传入的大文本快照。

## 9. 后台任务规则

- 六类任务属于 `feasibility-report` 任务组，采用 `group-exclusive`。
- 第一版整个可研模块同一时间只运行一个耗时任务，与技术方案当前锁策略保持一致。
- 任务启动后先写入 `running` 状态，再清理需要失效的下游数据。
- 页面卸载、切换菜单或切换项目不取消任务。
- 页面重新挂载后先读取 Store，再订阅任务事件，最后调用 `getActiveTasks()` 回放活动任务。
- Store 中存在 `running`、`pausing` 或 `stopping`，但 Main 没有对应活动任务时，恢复为 `error`，错误信息统一为“上次任务未完成，请重新执行”。
- 正文生成支持 `pause`、`resume` 和 `onlyMissing`；暂停点只发生在完整叶子小节写入之后。
- 目录和 JSON 输出失败时复用现有 JSON 修复链路。
- 目录 AI 调整不依赖持久 Agent 会话，每次把当前完整目录和本次调整要求一并提交模型。

## 10. 数据失效与清空规则

| 变更动作 | 保留 | 清空 |
| --- | --- | --- |
| 修改项目名称、类型或建设参数 | 资料文件 | 资料分析、目录、关键参数、正文及相关任务缓存 |
| 导入或移除资料文件 | 项目资料、剩余资料 | 资料分析、目录、关键参数、正文及相关任务缓存 |
| 手动修改资料分析 | 项目资料、资料文件、当前分析 | 目录、关键参数、正文及相关任务缓存 |
| 修改目录模板、目标字数或知识库引用 | 项目资料、资料文件、资料分析 | 目录、关键参数、正文及相关任务缓存 |
| 重新生成或手动调整目录结构 | 当前目录 | 关键参数、全部正文、正文小节状态及相关任务缓存 |
| 修改关键参数 | 项目资料、分析、目录、当前关键参数 | 全部正文、正文小节状态及相关任务缓存 |
| 手动编辑单个正文小节 | 其他全部数据 | 不清空；该节点标记为 `manual` |
| 重新生成选定正文小节 | 未选中的正文 | 任务确认启动后清空选中节点旧正文 |
| 重置项目 | 项目壳和项目名称 | 当前项目全部业务数据和导入图片 |
| 删除项目 | 其他项目 | 当前项目数据库、Markdown 和导入图片，删除后不可恢复 |

所有清空动作在 Main 侧完成。任务未成功启动前，不提前清空持久化结果。

## 11. Prompt 与内容约束

- Prompt 统一放在 Electron Main 服务文件中，不在组件内硬编码大段 Prompt。
- 资料分析必须区分“材料明确事实”“合理推导”“待确认信息”，不得把缺失数字补写成确定事实。
- 目录生成最多三级，标题不含 Markdown 标记和手写编号。
- 关键参数对投资额、周期、建设规模、资金来源和效益指标建立统一口径。
- 正文引用知识库内容时只使用当前叶子关联条目，避免把完整知识库注入每次请求。
- Mermaid 图以 Markdown `mermaid` 代码块保存，不保存模型生成的原始 HTML。
- 可研报告属于专业咨询材料，页面和导出文件均提示用户进行人工复核。

## 12. UI 与交互约束

- 页面根容器使用 `height: 100%` 和 `min-height: 0`，长内容在页面内部滚动。
- 复用现有项目卡片、步骤导航、上传区、Markdown 编辑器、预览器、进度条、Dialog、Toast 和 `FloatingToolbar`。
- 不迁移来源项目独立的共享 UI 组件；缺失能力优先用本项目现有组件组合。
- Markdown 渲染传入 `allowRawHtml={false}`。
- 成功、失败和警告统一使用 `ToastProvider`；确认操作使用项目内 Dialog。
- 运行任务时允许离开页面，并明确提示“后台任务将继续运行”。

## 13. Word 导出边界

第一版复用现有 `window.yibiao.export.exportWord()` 和进度事件，增加可研专用载荷：

- 项目名称和项目基础信息。
- 是否包含封面、编制说明和基本情况附表。
- 编制单位、密级和文档编号。
- 完整目录及 `outline[*].content`。

导出服务负责：

- 可研封面和编制说明。
- Word 原生目录结构和章节编号。
- Markdown 表格、图片和 Mermaid 转换。
- 附表生成和中文文件名处理。
- 导出进度、警告和最终路径返回。

第一版不提供模板库选择；后续如本项目建立统一导出模板模块，再接入模板配置。

## 14. 安全、许可与纯净版要求

- 不新增遥测、Analytics、远程公告或项目自有统计接口。
- 仅在用户主动导入文件、调用模型或导出时执行对应能力。
- Main 侧文件读写显式使用 UTF-8，并按 Windows 中文路径验证。
- 删除文件前通过 Store 解析出单个具体项目路径，不使用宽泛目录或未校验变量。
- 来源仓库与本项目均使用 AGPL-3.0-only；本次功能集成不新增 `NOTICE` 文件。
