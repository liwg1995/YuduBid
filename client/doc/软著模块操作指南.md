# 软件著作权模块操作指南

## 使用范围

软件著作权模块用于从本地软件项目中整理申请表信息、操作手册、代码鉴别材料和申报辅助文档。模块不代替著作权登记机构的实际受理要求，所有材料在提交前都需人工复核。

## 推荐操作顺序

1. 在“软件著作 > 软著项目”中新建或选择项目档案。
2. 直接选择本地源码目录，或到“源码准备”页面确认当前项目的源码文件范围。
3. 补全软件全称、版本号、著作权人、开发完成日期和官网填报辅助字段。
4. 选择操作手册图片方式，并完成图片说明、顺序和插入位置检查；手工图片使用 PNG 或 JPEG。
5. 生成草稿，逐份检查业务理解、申请表信息、操作手册和代码材料。
6. 运行完整检查，处理字段、代码、图片和跨材料一致性问题。
7. 确认草稿，生成不可变的确认快照。
8. 导出正式资料，使用完整性通过的最新交付批次。
9. 在“申报辅助”中复制官网字段，生成《申报提交说明》。
10. 根据实际受理系统调整格式，保留最终提交版和回执。

## 项目档案

每个软著项目具有独立的源码准备状态、字段、草稿、图片、确认快照和交付历史。

- “新建”创建空白工作区。
- “复制”保留当前项目的材料作为新项目起点。
- “归档”隐藏已完成项目，不会删除本地数据。
- 任务运行或草稿未保存时，不建议切换项目。

## 代码材料

代码材料只从选定项目的真实源码中抽取。默认清理注释、空行和敏感信息，并按50行一页组织。

- 材料超过60页时，生成前30页和后30页。
- 材料不足60页时，保留全部有效代码。
- 可手动补充候选文件或排除不适合提交的文件。
- 改变抽取规则、补充文件或排除文件后，需重新抽取。
- 密钥、个人信息或高风险内容需在审查结果中处理。

## 草稿和版本

编辑草稿前和恢复历史版本前，系统会自动留存版本。修改草稿、申请字段、图片或代码材料后，已确认状态会失效，需重新检查、确认和导出。

## 确认快照和交付批次

确认草稿时，系统会复制当前草稿和图片，生成文件摘要清单。正式导出仅使用该快照，避免后续编辑污染已确认材料。

每次导出会生成独立批次，包含：

- 申请表信息 TXT。
- 操作手册 DOCX。
- 代码材料 DOCX 和 TXT。
- 生成报告与导出说明。
- 申报提交说明。
- 交付清单和 ZIP 交付包。

“完整性通过”表示批次中记录的文件摘要与当前文件一致。出现“文件缺失”或“摘要不一致”时，请使用未修改的原批次，或重新确认并导出。

## 申报辅助

申报辅助区提供字段映射、长度提示、待补充内容检查、文件命名检查和提交风险清单。

- 复制的字段需在实际登记系统中再次校对。
- 只有与当前确认快照一致的交付批次，才会计入当前提交检查。
- 权属证明、身份证明和实际受理口径必须人工核对。

## 异常恢复

- 客户端在任务运行中退出后，下次打开会将任务标记为“上次任务未完成”，保留已有数据并允许重试。
- 确认快照丢失或损坏时，旧确认状态会失效，需重新检查和确认草稿。
- 交付文件被修改后，历史批次会显示摘要不一致。
- 如出现高于当前客户端支持版本的工作区提示，请升级客户端，不要手工修改状态文件。

## 本地数据与备份

软著数据保存在 Electron `userData/workspace/software-copyright/` 及其项目档案目录中。备份时建议关闭客户端，整体复制软著工作区和项目档案目录。

不要只备份 `state.json`，草稿、图片、确认快照、正式资料和历史版本都是独立文件。

## 发布约束

- Windows 和 macOS 当前未接入代码签名，系统可能显示未签名应用提示。
- 生产发布前应运行 `npm run verify:software-copyright:release`。
- 完成目录打包后应运行 `npm run verify:software-copyright:artifact -- <产物路径>`，检查应用版本、核心文件和原生模块。
- 人工验收按《软著模块发布候选版验收清单》逐项记录，并在真实 Windows 环境复核中文路径和导出。
- 修改 Electron Main 或 preload 后，还应执行相应的 `node --check` 和本地客户端验收。
