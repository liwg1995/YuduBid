## 两套界面

- **守矩**：保留上游步骤、预设页签、结果与修复交互；格式要求恢复双列设置密度，同时适配本地多企业资信库、暗色主题及工具栏定位。
- **启象**：共用完整业务功能，四步统一采用步骤概览和同一个工作区；第一步采用独立双栏拖入区与文档详情，后续使用左侧规则分类、两列编辑区和底部操作栏；窄窗口收成横向规则页签。
- 上传样式限制在暗标页面内，选项卡组件使用独立类名，避免覆盖其他功能页。
- 已用隔离工作区的真实 Electron 页面截图检查守矩明暗、启象暗色、四个步骤、开关尺寸、底部操作栏及窄窗口；用户仍需在完整应用中手动验收。

## 本地架构适配

- Renderer 仅通过 `window.yibiao` 访问；Main 使用独立控制器，IPC 负责转发。
- 引擎来自 `openxmlhelper/` 上游源码。开发机需 .NET 10 SDK 构建；分发使用自包含引擎，用户不必安装 .NET。
- 在 `client/` 执行 `npm run build:blind-helper`；发布 CI 构建 Windows x64、macOS Intel/Apple Silicon 引擎并随客户端打包。
- AI 任务使用本地模型服务适配器，保留上游复核/修复提示词、工具和结果校验，未引入上游整套 Agent 运行时。
- 多企业资信库：仅一家时自动选择；多家时手动选择，只读取选中企业敏感词。
- SQLite v33/v34 保存完整预设、招标依据、结果、修复对账、任务及企业选择；暗标日志单独命名。
- 重置任务保留预设及其招标原文；未接入上游遥测、远程公告或统计服务。

## 手动验收

1. 守矩对照上游检查四个页面、预设各页签、弹窗、滚动和工具栏；启项检查同样入口是否齐全。
2. 导入包含批注、修订、彩色文字、表格和图片的 DOCX，检查定位和分类，选择部分规则修复并导出。
3. 从真实招标文件生成预设，核对字段依据及人工检查条款，使用自己的模型执行 AI 复核/修复。
4. 切换资信企业，核对敏感词；检查切页、重启、重置和重新导入后的状态。
5. 用 Word/WPS 打开修复副本核对分页、字体和图片；图片 OCR、最终页数/版式仍需人工复核，这也是上游能力限制。
