# Agent 化渐进式改造方案

## 改造目标

在不改变现有菜单、页面、IPC、业务 Store 和导出结果权威来源的前提下，为售前工作台、招投标、公文写作、课题申报、项目协作、论文导师、软件著作和专利生成逐步增加受控 Agent 编排能力。

Agent 只负责目标理解、步骤规划和工具编排。文件读写、状态迁移、任务锁、格式校验、删除覆盖和正式产物提交继续由确定性业务代码执行。

## 不可破坏的兼容边界

1. 现有 IPC 通道在对应模块完成迁移和验收前不删除、不改名、不改变返回结构。
2. 现有 Renderer 页面继续读取原 Store；Agent 运行记录不成为业务结果的第二权威来源。
3. 技术方案正文继续以 `outlineData.outline[*].content` 为权威来源。
4. Agent 生成内容先作为候选产物，经过校验或用户确认后再提交到业务 Store。
5. 默认不开启 Agent 入口；每个业务域使用独立功能开关，支持回退到原流程。
6. Renderer 不直接获得 Node、文件系统、数据库或任意 Tool 调用能力。
7. 删除、覆盖、批量修改、正式导出等高风险 Tool 必须声明审批策略。

## 分阶段计划

### 阶段 0：基线与契约

- 建立 Tool Registry 和 Agent Registry 的纯底层契约。
- 不在 Electron Main 初始化，不注册 IPC，不改变任何生产调用链。
- 为注册、权限和强制审批行为增加离线验证。
- 逐模块补充现有输入、状态、产物和恢复行为基线。

### 阶段 1：只读 Tool 试点

- 首先包装状态读取、材料摘要和任务查询等只读能力。
- Agent 只能生成执行建议，不得写入业务 Store。
- 对比 Agent 建议与现有人工流程，不改变用户默认入口。

当前已建立招投标只读 Tool：技术方案项目列表、工作区摘要、活动任务和知识库摘要。招投标 Agent 默认关闭，且尚未接入 Main、IPC 和 Renderer。

只读 dry-run Runtime 已建立：运行时按 Agent 白名单执行 Tool，并在调用前再次检查 Tool 风险和审批策略；任何非只读 Tool 都会被拒绝。当前规划器仅根据结构化摘要给出确定性建议，不调用模型，也不进入生产调用链。

Agent Run 独立 Store 已建立：使用 `workspace/agent-runs/runs.json` 保存完成或失败的 dry-run 记录，采用 UTF-8 原子写入、数量裁剪和敏感字段过滤。该 Store 不修改现有 SQLite 表，不作为任何业务结果的权威来源，当前仍未接入生产初始化。

Approval 审批服务已建立：审批请求保存在独立的 `workspace/agent-runs/approvals.json`，只保存操作摘要和参数 SHA-256 哈希，不保存完整 Tool 参数。批准记录绑定 Run、Agent、Tool 和参数，限时有效且只能消费一次。当前没有生产注册的写 Tool，也没有开放审批 IPC。

首个实验性写 Tool 已建立：`bid.technical-plan.outline.start` 只包装现有目录生成任务入口，并复用原任务锁、清空和持久化规则。Tool Registry 要求传入与 Run、Agent、Tool 和参数哈希完全一致的已消费审批凭据。该 Tool 仅在离线验证中用模拟 Service 注册，尚未进入 Main 生产注册表。

审批执行状态机已建立：写操作先创建 `waiting_approval` Run，批准后由 Runtime 消费审批并执行 Tool，随后落盘 `running/success/error` 状态。待执行的完整参数只保存在当前 Main 进程内；Runtime 重建或应用重启后不会自动恢复写操作，用户必须重新发起并确认。当前状态机仍只连接模拟 Service。

统一 Agent Host 工厂已建立：Host 组装 Registry、Runtime、Run Store 和 Approval Service，使用 `enabled` 与 `experimentalWritesEnabled` 两层开关。关闭时不会注册能力或创建 Agent 数据目录；只开启基础开关时仅提供招投标 dry-run，目录生成 Tool 仍不可用。Host 尚未在 Electron Main 中创建。

Agent Host 已接入 Electron Main；默认配置下保持关闭。当前只注册状态查询与 dry-run IPC，没有注册审批或执行 IPC。

隐藏 Agent 配置契约已加入 `user_config.json`：`agent_settings.enabled` 与 `agent_settings.experimental_writes_enabled` 默认均为 `false`，并使用严格布尔值归一化；只有基础开关为真时实验写开关才可能为真。旧配置会安全补齐默认值，设置页面暂不展示这些选项。

开发者只读试运行已接线：Main 只有在 `developer_mode === true` 且 `agent_settings.enabled === true` 时才组装真实 Agent Host，并开放 `agent:get-status`、`agent:run-dry` 两个 bridge 方法。实验写开关仍被 Main 强制设为 `false`，审批和执行 IPC 均不存在；设置页面没有入口。配置读取失败或 SQLite 初始化失败时 Agent 保持关闭，不影响现有业务 IPC 的降级逻辑。

开发者测试页已加入“Agent 只读诊断”面板，用于查看 Host 状态并针对技术方案项目运行 dry-run。面板只调用状态和只读诊断 bridge，没有审批、执行或写 Tool 控件；正式业务菜单和页面保持不变。

技术方案 Agent 影子运行已接入开发者测试页：必须指定真实项目 ID，读取工作区结构化摘要，将 Agent 建议动作与当前工作台 `step` 对应的既有导航动作进行对照，并在独立 Agent Run Store 中记录一致性结果。影子结果的 `executed` 固定为 `false`，不会启动任务、修改目录、生成正文或写入业务 Store。

影子运行观测面板已建立：通过只读 `agent:get-shadow-report` 返回总次数、已评估数、一致数、偏差数、失败数和一致率，并最多展示近期 50 条裁剪记录。报告不返回 Tool 步骤结果、正文或完整建议，只用于迁移质量观察；功能关闭时返回空统计。

影子偏差已增加确定性原因分类：`ACTIVE_TASK_CONFLICT`、`WORKBENCH_STEP_BEHIND`、`WORKBENCH_STEP_AHEAD`、`STATE_INCONSISTENT`，一致时标记为 `ALIGNED`。分类优先识别正在运行的任务，再比较现有工作台步骤与摘要推导的安全下一动作；观测面板按原因聚合展示，仍不参与业务决策或执行。

Agent 安全准入门已建立：当前策略要求至少 20 次有效影子评估、决策一致率不低于 95%、运行失败率不高于 2%，且活动任务冲突、工作台步骤超前、状态不一致等高风险偏差合计为 0。结果仅分为“样本不足”“未通过”“达到人工确认试点门槛”，不会读取或修改功能开关，也不会自动注册、审批或执行写 Tool。

人工确认执行试点的只读预览已建立：当前仅预览“启动技术方案目录生成”，复用未来写 Tool 的同一参数归一化契约，返回脱敏参数、风险和审批级别、现有目录/全局事实/正文的影响范围、后台任务影响及全部阻断原因。预览固定声明 `previewOnly: true`、`approvalCreated: false`、`executionStarted: false`，不创建审批记录、不调用任务 Service，也不开放确认或执行控件。

不可执行审批草稿已建立：草稿只能从服务端重新生成的只读预览创建，保存脱敏参数、影响范围、阻断原因和完整参数 SHA-256 哈希，不保存完整执行参数。草稿默认 30 分钟过期、最长 24 小时，可撤销且不可重复撤销；状态包括 `active`、`blocked`、`expired`、`revoked`。所有草稿均固定 `approvable: false`、`executable: false`，当前 IPC 和页面仍没有批准或执行入口。

审批草稿完整性校验已建立：草稿使用字段递归排序后的规范化 JSON 计算 SHA-256，读取、列出和撤销前均验证完整性；状态变化后重新计算校验值。无校验值的早期草稿会原地迁移，校验失败的草稿从主文件移除，只将草稿 ID、检测时间、原因和校验摘要写入独立隔离文件，不保留或返回被篡改内容。该校验用于发现磁盘损坏或意外修改，不作为抵抗本机恶意用户的密码学信任边界。

审批草稿状态事件日志已建立：创建、完整性迁移、自动过期、撤销和隔离分别记录 `CREATED`、`MIGRATED`、`EXPIRED`、`REVOKED`、`QUARANTINED` 事件。事件只包含草稿 ID、前后状态、原因和时间，不包含草稿内容或执行参数；每条事件绑定前一条摘要形成 SHA-256 链，列表接口返回链完整性状态。日志最多保留 500 条，截断时校验保留链段，不参与审批或执行。

审批策略快照已建立：新建草稿固化 `agent-admission/v1` 策略版本、创建时的阈值、四项检查结果、准入状态，以及目录生成 Tool `0.1.0` 的 ID、风险和审批契约，并为快照单独计算 SHA-256。快照同时受草稿整体完整性校验保护，后续策略变化不会改写历史草稿；无法证明原始策略的旧草稿保持无快照状态，不伪造补全。

审批草稿状态漂移检测已建立：草稿创建时对 Tool 契约、脱敏参数、影响范围、阻断条件和准入策略计算上下文指纹；同一项目再次生成服务端预览或创建新草稿时重新计算。指纹变化或旧草稿缺少指纹时，原 `active/blocked` 草稿自动改为不可恢复的 `stale`，记录 `STALE` 事件和 `CONTEXT_DRIFT/MISSING_CONTEXT_FINGERPRINT` 原因；已撤销、过期或过时草稿不重复处理，也不会触发业务执行。

只读审批包预览已建立：从通过完整性校验的草稿即时组合操作摘要、脱敏参数、影响范围、阻断条件、策略快照、漂移状态、草稿完整性和审计链摘要，并计算独立的 `agent-approval-package/v1` SHA-256。审批包只在 Main 内存中返回，固定 `inMemoryOnly/fileCreated/submitted/approvable/executable` 为安全值，不生成文件、不追加业务记录、不提交审批，也不携带完整执行参数。

审批包二次校验器已建立：对 Renderer 回传的内存审批包限制最大 200 KB，重新计算包摘要和策略快照摘要，并与当前通过完整性校验的草稿、上下文指纹、审计链及事件数量快照对照，同时检查所有不可审批/不可执行安全标记。校验器只返回逐项布尔报告和重新计算的摘要，固定 `persisted/submitted/executed` 为 `false`；内容、策略、草稿或事件链任一漂移都会使整体校验失败。

### 技术方案 Agent 安全试点收敛计划

- 阶段性总验收已完成，功能开关、接口边界、数据文件、回滚方式和后续领域复用清单见《Agent技术方案试点验收报告》；本试点冻结为 `frozen-read-only`。
- 当前剩余步骤为 0，不再继续增加本试点安全外壳。是否进入其他业务 Agent 接入或真实人工确认执行，由后续明确决定。

### 阶段 2：招投标辅助 Agent

- 复用现有 `taskService.cjs`，封装技术方案任务启动和状态查询 Tool。
- 写操作通过现有 Service 执行，保持任务锁、清空规则和恢复语义。
- Agent 生成目录或正文前增加确认节点。

验收状态：本阶段已完成。技术方案业务工作台已接入 `bid-agent` 的项目级规划入口。Agent 可在用户确认后复用原 `startBidAnalysis`、`startOutlineGeneration` 和 `startGlobalFactsGeneration` 后台任务；上传材料、正文参数配置以及复核导出仍导航至原页面完成。原步骤导航、生成按钮、任务恢复和导出入口全部保留，Agent 开关关闭时不显示新入口。规划器已补齐全局事实前置判断，项目状态变化后页面清除旧建议。招投标阶段到此收口，不再追加安全设施。

### 阶段 3：统一运行时

- 增加 Agent Run、Step、Artifact、Approval 和 Event 持久化。
- 统一取消、暂停、恢复、幂等键和错误分类。
- 逐个迁移各业务服务自有的 `activeTask`，每次只迁移一个模块。

### 阶段 4：其余领域 Agent

- 依次接入公文、论文、专利、课题申报、售前、软件著作和项目协作。
- 每个 Agent 只获得明确声明的 Tool 和资源范围。
- 每个模块保留旧入口，完成对照验收后再决定是否默认启用。

#### 售前工作台 Agent（本阶段已验收）

- 已注册独立 `presales-agent`，只读取售前项目列表和脱敏工作区摘要。
- 确定性规划器沿用原业务顺序：客户材料、材料分析、调研准备、方案架构、图表工场、汇报页纲、人工复核与导出。
- dry-run 与 shadow-run 均复用统一运行记录，但不调用售前生成、保存、导入、删除或导出方法。
- 开发者测试页可选择“售前工作台”执行只读诊断和影子对照；技术方案执行预览与审批草稿入口在该工作流下禁用。
- 原售前页面、IPC、Service、状态文件和默认用户路径未改变，功能开关关闭时不存在 Agent 调用。
- Agent 开关启用时，售前工作台展示“规划下一步”；用户点击执行建议后还需在项目级确认框中确认，随后直接复用原有五个生成函数。原阶段按钮完整保留，可随时绕过 Agent 使用旧流程。
- 项目资料、输入或生成结果发生变化时，页面立即清除旧 Agent 建议，必须基于最新状态重新规划，避免执行过时建议。
- 售前阶段到此收口，不再追加基础安全设施。

当前已完成售前工作台、招投标两个业务域；其余待迁移业务域为公文写作、课题申报、项目协作、论文导师、软件著作、专利生成，共 6 个。

#### 公文写作 Agent（本阶段已验收）

- 已注册独立 `official-document-agent`，只读取文种、要素是否齐备、草稿/检查/修订状态和活动任务摘要，不读取或返回公文正文。
- 规划顺序固定为补充起草要素、生成草稿、格式检查、降 AI 味润色、人工复核与 Word 导出。
- 公文业务页面在 Agent 开关启用时显示规划入口；生成、检查和润色在用户确认后复用原 `officialDocument` bridge 方法，模板、导入、手工编辑、历史版本和导出入口保持不变。
- 工作区更新时间变化后旧建议立即清除；运行中任务只建议等待，不会重复启动。
- 公文写作阶段到此收口。当前剩余课题申报、项目协作、论文导师、软件著作、专利生成，共 5 个业务域。

#### 课题申报 Agent（本阶段已验收）

- 已注册 `grant-application-agent`，只读取项目、档案完整度、四阶段输入输出、申报书模块数量、终审状态和活动任务摘要。
- 规划顺序为启动诊断、选题政策、申报书模块、整稿质量检查、评审答辩和人工复核导出。
- 用户确认后复用原阶段生成、缺失模块批量生成和整稿质量检查方法；需要补充材料或导出时回到原页面处理。
- 项目状态变化后清除旧建议，运行中任务不重复启动；原项目管理、模板填充、模块编辑、检测和导出入口保持不变。
- 课题申报阶段到此收口。当前剩余项目协作、论文导师、软件著作、专利生成，共 4 个业务域。

#### 项目协作 Agent（本阶段已验收）

- 项目状态或项目 ID 变化后清除旧建议，运行中任务不重复启动；Agent 开关关闭时页面不显示规划入口。
- 项目协作阶段到此收口。当前剩余论文导师、软件著作、专利生成，共 3 个业务域。

#### 软件著作 Agent（本阶段已验收）

- 已注册 `software-copyright-agent`，只读取源码是否就绪、必填字段缺失数、草稿/代码材料/确认快照/人工复核/交付状态和活动任务摘要，不读取源码或申报材料正文。
- 规划沿用准备源码与登记信息、生成草稿、核对材料、确认快照、申报人工复核、提交前总检与导出的原六阶段流程。
- 草稿生成和快照确认均在用户确认后复用原 `handleGenerateDraft()`、`handleConfirmDraft()`；其余人工节点只导航到原页面区域，不自动代替人工勾选或导出。
- 工作区状态变化后清除旧建议，运行中任务不重复启动；原案件管理、草稿编辑、版本历史、图片管理、代码材料、申报辅助及交付批次入口保持不变。
- 软件著作阶段到此收口。当前仅剩专利生成 1 个业务域。

#### 专利生成 Agent（本阶段已验收）

- 已注册 `patent-generation-agent`，只读取案件、项目、候选点、待补事实数量、交底书、查新、修订和活动任务摘要，不读取源码、事实内容、查新材料或交底书正文。
- 规划沿用案件准备、项目导入、专利挖掘、主专利点选择、事实补充、交底书生成、查新增强、修订和人工复核导出的原流程。
- 专利挖掘、事实补充建议和交底书生成在用户确认后复用原业务方法；主专利点选择、事实确认、查新材料、修订要求和最终导出仍由用户在原页面完成。
- 状态或案件变化后清除旧建议，运行中任务不重复启动；原暂停/继续/停止、草稿编辑、质量提示、查新、版本历史和 Word 导出入口保持不变。
- 专利生成阶段到此收口。计划内售前工作台、招投标、公文写作、课题申报、项目协作、论文导师、软件著作和专利生成共 8 个业务域已全部完成 Agent 接入。

#### 内测开放与诊断收口

- 设置页在开发者模式下提供“Agent 工作台（内测）”开关，保存并重启后生效；Main 仍同时校验开发者模式与 Agent 开关，不默认向普通用户开放。
- 设置页始终强制 `experimental_writes_enabled=false`，业务执行只复用各页面既有方法及其确认流程，不开放 Agent 通用写 Tool。
- 开发者诊断页已补齐全部 8 个业务域；只有技术方案与已有方案扩写显示目录影响预览和不可执行草稿，其余领域仅提供只读诊断与影子对照。

### 阶段 5：跨 Agent 协作

- 仅传递结构化产物引用，不直接共享整个工作目录或全部历史上下文。
- 跨业务写入必须显示目标项目、变更摘要并经用户确认。

## Tool 最小契约

每个 Tool 必须声明：

- 稳定 ID 和 SemVer 版本；
- 中文名称和用途；
- 输入、输出 Schema；
- 权限；
- 风险等级；
- 审批策略；
- 是否幂等；
- 所属任务组（如适用）。

## 阶段验收门

每个阶段至少满足：

1. `npm run verify:agent-foundation` 通过。
2. `npm run build` 通过。
3. 涉及 Main/preload/IPC 时，对相关 `.cjs` 执行 `node --check`。
4. 新旧入口对同一业务样本产生兼容的 Store 状态和正式产物。
5. 页面卸载不取消任务，应用重启后中断状态符合原业务约定。
6. 功能开关关闭时，调用路径与改造前一致。
